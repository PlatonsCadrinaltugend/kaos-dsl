# KAOS DSL
This project is based on the KAOS UML profile defined by Heaven and Finkelstein in 2004. It is extended by the element 'Obstacle'.
### Getting Started

#### Prerequisites

- Java JDK 17

- Scala 3.8.4 and sbt 1.12.14 

- Graphviz (optional, required for visualization)

In order to run the code, the command `sbt run` can be used in the kaos-dsl directory.
To run the tests, `sbt test` can be used.

#### Defining a model

A KAOS model can be defined in model.kaos. It is the default file for the input. Custom file sources can be declared by running `sbt "run custom/path/model.kaos"`.

### Project Structure

- `model` contains the AST and the Type definitions
- `parser` contains the parser
- `validation` contains the validation logic
- `feedback` contains the error representation
- `test` contains the automated MUnit tests
- `visualizer` contains the visualization

### DSL Syntax

Elements are defined using the syntax:
```text 
<concept keyword> <identifier>
```
The following elements are supported:

- `goal`
- `requisite`
- `requirement`
- `assumption`
- `object`
- `entity`
- `event`
- `action`
- `agent`
- `obstacle`

Each Element can be assigned properties.

```text 
<concept keyword> <identifier> {
	<property name> = <property value>
}
```

In this DSL the following properties are supported:

| Property | Type/Allowed Value | Applicable to | Required? |
|---|---|---|---|
| `informalDef` | String | all elements| no |
|`formalDef`| String | `goal`, `requisite`,`action`| no |
|`realm`|{domain, software}|`agent`| yes |

Relationships are declared using this syntax:

```text
<sourceID> <relationshipType> <targetID>
```
The following relationship types are supported.

| Relationship | Textual Representation |
|---|---|
| reduces | `<goal/requisite> reduces <goal>` |
| conflicts | `<goal> conflicts <goal>` |
| concerns | `<goal> concerns <object>` |
| ensures | `<object> ensures <requisite>` |
| operationalizes| `<action> operationalizes <requisite>` |
| responsibility | `<agent> is responsible for <requisite>` |
| performs | `<agent> performs <action>` |
| capability | `<agent> is capable of <action>` |
| monitors | `<agent> monitors <object>` |
| controls | `<agent> controls <object>` |
| input | `<action> has input <object>` |
| output | `<action> has output <object>` |
| obstructs | `<obstacle> obstructs <goal/requisite>` |
| refines | `<obstacle> refines <obstacle>` |
| resolves | `<requirement> resolves <obstacle>` |

### Example
In `model.kaos` a small KAOS model can be found. Its interpretation is visualized in `ast.svg` and `ast_uml.svg`. `ast.svg` shows the internal AST structure generated by the parser. `ast_uml.svg` shows the UML-based visualized model following the definitions by Heaven and Finkelstein.

### Validation
After parsing the model is validated. `validator.scala` is the entry point for the validation. It will check for many types of errors. To give a few examples:
- `duplicate identifier error`
- `unresolved reference error`
- `relationship type error`
- `invalid property assignment error`
- `...`

If an error is detected, the location and error category are reported. Unlike syntax errors, validation errors are collected and returned as a list after all validation steps have been performed.

 ### Current Limitations

 - Properties can only be strings
 - The parser can only report a single syntax error at once
